# LadyTube 追加機能 (server/ext)

LadyTube のうち、派生元の WomanLive に足した機能の詳細です。v2.1.1 までは WomanLive 本体を改変しないアドオン
（WomanLive 拡張機能）として配っていたもので、サーバー側はその作りのまま `server/ext/` に入っています。
画面の側は v3.3.0 で本体の画面（`client/src`）に移しました。導入方法はルートの README を見てください。

## 仕組み
- **読み込み**: 本体の `server/index.js` が express のアプリを作った直後に `require('./ext')(app)` で拡張を読み込みます。
  使用中ライブラリの DB は、本体の `server/db.js` が `server/ext/library.js` に聞いてから開きます。
- **検索**: 本体の一覧 `/api/videos` と件数 `/api/videos/count` は、`server/ext/routes/search.js` が返します
  (本体 `server/services/videoService.js` の `getVideos`/`getVideoCount` から呼ぶ)。項目検索・表示動画名の照合・
  拡張のソート・品番でまとめる表示は、ここで扱います。
- 追加データは `videos.db` の**新規テーブル**（`ext_*`）に保存。WomanLive から引き継いだテーブルの形は変えていません。
- **ライブラリ**を作ると、ライブラリごとの DB ファイル（`libraries\<ID>\videos.db`）を本体に開かせます（後述の「ライブラリ」）。
- **画面**: 追加機能の画面は本体の React です。ページは `client/src/pages/`（`SeriesPage.jsx`・`TagsPage.jsx`・`PerformersPage.jsx`・
  `PerformerPage.jsx`・`MakersPage.jsx`・`BookmarksPage.jsx`。カレンダーは `CalendarPage.jsx`）、部品は `client/src/components/Ext*.jsx`、
  スタイルは `client/src/womanlive-ext.css`（`.wlext-*`）です。v3.2.1 までは `server/ext/public` の JS と CSS を
  index.html に差し込んでいました。今の `server/ext/inject.js` は、使用中のライブラリを index.html に埋め込むだけです。

## ライブラリ
動画・設定・メタデータを、ライブラリ単位で分けて切り替えます(例: AV とそれ以外)。
- **ライブラリ1つ = DB ファイル1つ**。既定のライブラリは今までの `videos.db` で、本体だけで起動したときもこれが開きます。
  追加したライブラリは `libraries\<ID>\videos.db`、一覧と使用中は `libraries\libraries.json` に保存します。
- **ライブラリごとに分かれるもの**: スキャン対象フォルダ・拡張子・除外パターン、動画一覧・サムネイル・スクリーンショット・タグ・
  再生履歴、拡張メタデータ(評価・品番・メーカー等)、ブックマーク、カバー画像、タグサムネイル、
  カバー画像フォルダ、関連動画の重み、ブラウザの検索履歴。
- **全ライブラリ共通のもの**: 出演者(プロフィール・画像)、メーカー情報(画像・キャッチコピー等)、公開設定、プリセットタグ(グループ配置を含む)、
  FANZA API ID、出演者タグのプリセットと自動付与ルール。出演者は既定のライブラリの DB に置き、
  追加ライブラリで動いている間は既定の DB をつないで読み書きします。
- **管理画面の「ライブラリ」**: 一覧(動画数・サイズ・最終利用)、作成(空 / 今のライブラリの設定を引き継ぐ /
  今のライブラリを丸ごと複製)、名前変更、切り替え、削除。設定を引き継ぐ作成では、スキャン対象フォルダとカバー画像フォルダは引き継ぎません。
- **ほかの videos.db の取り込み**: 指定した `videos.db`(フォルダ指定も可)をコピーしてライブラリにします。元のファイルは変更しません。
  本体の今の形式と表・列を照合し、WomanLive 以外の DB や形式の違う DB は拒否します。出演者は名前で突き合わせて
  共通の出演者へまとめ、共通側で空の項目は取り込み元の値で埋めます。
- **切り替え**: ヘッダーのロゴの右(ライブラリが2つ以上あるとき)か、管理画面から行います。サーバーが自動で再起動し、
  ブラウザはホームを開き直します。スキャン中は切り替えられません。再生中の動画は止まります。
  起動時は前回使っていたライブラリを開きます。
- **切り替えと削除は、サーバーを動かしている PC(localhost)からのみ**行えます。削除したライブラリのファイルは
  `libraries\_trash` へ移します。使用中と既定のライブラリは削除できません。動画ファイルには触れません。
- **切り替え前に開いていた画面**: 動画の id はライブラリごとに振られるため、切り替え前の画面からの書き込み(評価・タグ・再生位置の
  保存など)はサーバーが拒否し、画面はホームを読み直します。ほかの端末で開いている画面も、次の操作か画面に戻ったときに読み直します。
- **出演者の削除**: 共通なので、削除するとほかのライブラリの動画からも紐付けを外します。バックアップの復元も出演者は全ライブラリに反映されます。
- 仕組み: 本体の `server/db.js` が起動時に `library.bootPath()` で使用中ライブラリのファイルを開き、開いた直後に
  `library.opened(db)` で既定のライブラリを繋ぎます。切り替えではサーバーが終了コード 75 で終わり、`ladytube.bat` が
  起動し直します(コンソール画面はそのまま。2回目以降は `-browser` を外すのでタブは増えません)。`ladytube.bat` 以外から
  起動したとき(bat が渡す `LADYTUBE_RESTART=1` が無いとき)は自動で再起動せず、次の起動から切り替わります。
- 実装: `server/ext/library.js`、`server/ext/routes/library.js`(書き込みのガード)。画面は `client/src/utils/library.jsx`
  (全リクエストへの印付け・切り替わったときの読み直し・切り替えの確認)、ヘッダーのライブラリ名は `ExtLibraryPill.jsx`
  (本体のヘッダー `Navbar.jsx` が置く)、管理画面の項目は `ExtLibrary.jsx` です。

## 動画の削除（ごみ箱へ）
検索結果の一括操作とリスト表示の「⋮」の「動画の削除」で、動画ファイルを Windows のごみ箱へ送ります(v3.4.0 までは即削除)。
- フォルダ側のカバー画像(カバー画像フォルダの同名の画像)もごみ箱へ送ります。
- DB からは、その動画のスクリーンショット・詳細情報・DB のカバー画像・ブックマーク・関連動画キャッシュを消します
  (同じ hash のファイルがほかに残っていれば消しません)。ごみ箱から動画を戻すと、次のスキャンで新しい動画として登録されます。
- **ごみ箱が使えない場所**(`\\server\share` のようなネットワークのパスと、ドライブのルートに `$RECYCLE.BIN` が無いドライブ。
  USB メモリや NAS を割り当てたドライブなど)の動画は、Windows がごみ箱に入れずに消します。確認画面に本数を出します。
- 使用中などでファイルを消せなかった動画は、DB の情報も残します(通知に件数を出します)。
- 実装: `server/ext/trash.js`(PowerShell から `SHFileOperation` を呼ぶ)、`routes/bulk.js` の `delete`/`deleteCheck`、
  画面は `client/src/components/ExtVideoMenu.jsx`。API `POST /ext/api/bulk/delete/check`(ごみ箱が使えない本数)、`POST /ext/api/bulk/delete`。

## ファイル名の変更
動画のファイル名をアプリの中で変えます。同じフォルダの中で名前を変え、DB の行は path と filename を書き換えるだけにするので、
id が変わらず、開いているページ・動画ページのアドレス・ブックマークはそのままです(エクスプローラーで変えると、次のスキャンで
別の id の行になり、それまでは再生もできません)。
- **1本ずつ**: 動画ページの表の「動画ファイル名」の行の鉛筆のボタンと、検索結果のリスト表示の「⋮」(1本のとき)の「ファイル名を変更」。
  名前の部分だけを入力します(拡張子は変わりません)。「ルールで作る」で、下のルールで作った名前を入力欄に入れます。
- **ルールで変える**: 一括操作と、まとめたカードの「⋮」の「ファイル名をルールで変更」。変える前と後の一覧を出し、「変更する(N本)」で変えます。
  名前が変わらない動画と、変えられない動画(理由を出します)は飛ばします。
- **一緒に変えるもの**: 同じ名前の字幕(`.ass`/`.vtt`/`.srt`。本体の字幕と同じ探し方)と、カバー画像のフォルダの同じ名前の画像
  (フォルダの画像はファイル名で探すため)。同じ名前のファイルが既にあるときは、そのファイルだけ変えずに知らせます。
- **変えないとき**: 使えない文字(`\ / : * ? " < > |`)・先頭の空白・末尾の点や空白・Windows の予約名(CON など)、同じ名前のファイルがある、
  パスが259文字を超える、ファイルが使用中(変換して再生している最中など)。DB を書き換えられなかったときは、ファイル名を元に戻します。
  大文字小文字だけの変更はできます。再生のために読んでいる最中のファイルは変えられます。
- PC からだけ行えます(ほかの端末では、メニューの項目を押せなくし、FANZA の確認画面のファイル名の行も出しません)。

### ファイル名のルール
管理画面の「ファイル名のルール」(既定は `{品番} {タイトル}`。設定 `ext_rename_rule`、全ライブラリ共通)。
- 項目: `{品番}` `{タイトル}`(表示動画名) `{出演者}`(3人まで、空白区切り) `{メーカー}` `{レーベル}` `{シリーズ}` `{公開日}`(YYYY-MM-DD)。
  知らない `{…}` はそのまま残します(書き間違いが確認の画面で見えます)。
- 今の名前の末尾のパート番号(`_2` など)は、いつも最後に付けます。品番そのものが `_数字` で終わる形(`010120_001` など)はパート番号とみなしません。
  タイトルの末尾の `_数字` は外してから使います。
- タイトルは60文字、名前全体は150文字で切ります。ファイル名に使えない文字は全角(`／` `：` `？` など)に置き換えます。
- 項目が空で名前が作れない動画は変えません。
- **FANZA の確認画面**: ルールで作る名前が今と違えば「ファイル名: 今 → 新」の行を出します。チェックした項目を反映したあとの値で作り直します。
  最初のチェックは、設定「動画情報を取得したら、ファイル名もルールで変える」(`ext_rename_on_fetch`、既定オフ)に従います。
- **一括取得とスキャン後の自動取得**: 上の設定がオンなら、項目を埋めた動画の名前をルールで変えます(結果に「ファイル名を変えた N本」)。
- 実装: `server/ext/rename.js`(名前の変更・ルールの一覧と適用)、`server/ext/filerule.mjs`(ルールから名前を作る。画面も
  `client/src/utils/fileRule.js` から同じものを使う)。画面は `client/src/components/ExtRename.jsx`(開くときに読む)。
  API `POST /ext/api/video/:id/rename { name }`、`POST /ext/api/rename/rule { ids, dryRun }`、FANZA の反映 `POST /ext/api/dmm/apply` の `rename`。

## PC からだけ行える操作
LAN 公開(スマホからのアクセス)をオンにしていると、同じネットワークの端末から画面を開けます。次の操作は、
**サーバーを動かしている PC(localhost)からだけ**行えます。ほかの端末からは API が 403 を返し、画面ではボタンを押せなくします。
- 動画の削除
- ファイル名の変更(「ファイル名の変更」)
- DMM の API ID とアフィリエイトID の表示と変更(本体の `/api/settings` も、ほかの端末には返しません)
- バックアップ(JSON)の書き出しと復元
- ライブラリの切り替えと削除(「ライブラリ」)
- LadyTube の終了(右上のメニュー。ほかの端末ではメニューに出しません)
- 起動時に開くブラウザの表示と変更(「起動時に開くブラウザ」)
- 実装: `server/ext/index.js` の `pcOnly` と `/api/settings` のフック、`routes/cover.js`。画面は `inject.js` が埋め込む
  `window.WLExtLibrary.local` を `client/src/utils/library.jsx` の `isLocalPC` で読みます。

## DB の自動バックアップ
起動したとき、前のバックアップから1日以上たっていれば、使用中のライブラリの DB を `backups\<ライブラリの ID>\videos-YYYYMMDD-HHmmss.db` に写します。
- ライブラリごとに新しい5つを残します。既定のライブラリの ID は `default`、追加したライブラリは `libraries` の中のフォルダ名です。
- 追加したライブラリで起動したときは、出演者とメーカーを持つ既定のライブラリの DB も写します。
- SQLite のバックアップ API で写すので、書き込み中でも整った状態のファイルになります。起動は待たせません。
- 戻し方はルートの README の「データ・バックアップ」にあります。
- 実装: `server/ext/autobackup.js`(`index.js` が起動時に呼ぶ)。

## ブックマーク
動画をフォルダ分けしてブックマークできます。
- 検索は**フォルダ名**で指定します(`@bookmark:"名前"`)。大文字小文字は区別せず、同名のフォルダが
  複数あれば両方が対象です。ブックマーク一覧のカードのリンクもこの形式です。
- 旧形式の**フォルダID指定(`@bookmark:2`)も引き続き動きます**。名前に一致しないときにIDとして
  解釈するので、保存済みのリンクは壊れません。
- フォルダ名に `"` や `\` が含まれていても、一覧のリンクは名前で組みます(`\"`・`\\` と書く。v3.3.0 まではID指定にしていました)。
- **ブックマークの画面**(カードや動画ページのボタン・一括操作の「ブックマーク追加」)は、フォルダを押すと選ぶだけで、
  **「OK」で保存**します。「キャンセル」(✕・Esc・画面の外も)は選択を捨てて閉じます。
  「＋追加」で作ったフォルダはその場で作成し(キャンセルしても残ります)、選んだ状態で並べます。
  一括操作では複数のフォルダを選べ、OK で選んだ動画をまとめて追加します(外す操作はありません)。
  途中で保存に失敗したときは通知を出し、画面を閉じません(もう一度 OK で残りを保存します)。
- 実装: ボタンは `client/src/components/ExtCardParts.jsx` の `ExtBookmarkButton`(カードは `ExtCardBadges`、動画ページの右下は `ExtWatchMeta.jsx` の `ExtWatchFabs` が置く)、フォルダを選ぶダイアログは同じファイルの `ExtBookmarkDialog`、ブックマーク済みの動画は `client/src/utils/bookmarks.js`。

## メンテナンス（参照されていないデータの削除）
動画ファイルが無くなったあとも残る拡張データを削除します。
- 本家のクリーンアップ(`DELETE /api/maintenance/metadata`)は `screenshots` と `metadata` しか消さないため、
  **そのままでは拡張側だけが hash をキーに残り続けます**。本家のクリーンアップに便乗して同じ条件で掃除します
  (本家は `res.json` をトランザクションの中で呼ぶので、同じトランザクションに乗り、後続の `VACUUM` で領域も回収されます)。
- 管理画面の「参照されていないデータの削除」から、件数を確認して単独実行もできます。
- 対象: `ext_video_meta` / `ext_video_cover` / `ext_bookmarks` / `ext_related`。
  関連動画キャッシュは元動画が消えた行に加え、参照先が消えた行も対象です
  (`rel_hash` が NULL の「該当なし」印は元動画が生きていれば残します)。
- 出演者は「関連動画のない出演者を一括削除」が別にあるため対象外。タグサムネイルとブックマークフォルダは
  hash に紐づかないため対象外です。
- 実装: `server/ext/routes/maintenance.js`、`index.js` のフック、
  API `GET /ext/api/maintenance/orphans`, `POST /ext/api/maintenance/cleanup`。

## 拡張メタデータ（詳細情報）
画面では「詳細情報」と呼びます。評価(★)・表示名・品番・公開日・シリーズ名・メーカー・レーベル・作品監督・出演者・ジャンル・作品紹介・URL を、
各動画ページ右下の「詳細情報を編集」ボタン（鉛筆）から編集し、動画ページに表示します。
- 右下の丸ボタンは横一列で、左から ブックマークに追加 / 動画情報を検索 / タグを編集 / 詳細情報を編集 の順です
  (その左に本体のイメージリストのボタン)。v3.8.0 までは、シアターモードでは縦に積んでいました。
  位置は `womanlive-ext.css` の `.wlext-*-fab`。
- 品番・シリーズ・メーカー等はクリックで同条件を検索（項目検索の `@series:"値"` のような語を付けて検索）。評価は検索・ソート可。
- 項目検索の値に `"` や `\` を含むときは、前に `\` を付けます（`@maker:"A\"B"`）。リンクはこの形で組みます
  (`client/src/utils/formatters.js` の `searchToken`。読み取りは `server/ext/routes/search.js` の `splitQuery` と `ExtFacets.jsx` の `parseQuery`)。
- 「表示動画名」を設定すると、一覧・検索でファイル名の代わりに表示されます。
- 検索画面右上の**「表示設定」に「動画表示名で表示する」**を追加しています（既定はON）。
  OFF にすると表示動画名を使わず、本家どおりファイル名で表示します。一覧・動画ページ・関連動画に効き、
  設定はブラウザに保存されます。並び替えの「表示名」は OFF でもそのまま使えます。
  ON のまま「拡張子を表示する」も ON にすると、表示動画名の後ろに元のファイルの拡張子を付けます。
- 実装: 一覧と動画ページの API が表示動画名を `ext_display_name` で返し、本体の画面が
  `client/src/utils/formatters.js` の `videoName` で名前を組み立てます。トグルは本体の表示設定(`UIOverlay.jsx`)にあります。
- 実装(動画ページ): 評価・ジャンル・出演者・品番などの表示と右下の丸ボタンは `client/src/components/ExtWatchMeta.jsx`(`WatchPage.jsx` が置く。本体のタグ編集ボタンの代わり)。詳細情報の読み込みと保存・タグ編集は `client/src/utils/videoMeta.js`、編集のダイアログは `ExtMetaEdit.jsx`(開くときに読む)、タグ選択は `ExtPresetTagDialog.jsx`、DMM 検索は `utils/metaSearch.jsx` と `ExtMetaSearch.jsx`。保存すると `wlext-meta-updated` で知らせ、動画ページが表示とタイトルを描き直します。

## 関連動画（メタデータ類似・事前計算）
動画ページの「関連動画」を、拡張メタデータの一致度で選出します。
- **本体の既定**: ファイルパスが前後する12件（実質「同フォルダ・ファイル名が近い動画」）のみ。
  メタデータを考慮していないため、これを類似度スコアリングに置き換えます。
- **採点**: シリーズ／出演者／メーカー／レーベル／監督／ジャンル／タグ／公開時期／評価の一致を計算し、
  上位12件を返します（**シリーズ最重視**が既定）。**重みは設定画面で調整可能**。
- **事前計算**: 結果は `ext_related` テーブルに保存。動画のメタを編集すると、その動画分は自動で再計算されます。設定画面「拡張機能：関連動画（重み付け）」の「全再計算」で全動画を一括計算も可能です。

## 動画ページの表示（作品情報・ファイル情報）
- タイトルの下は1行で、左に「N 回再生・3年7ヶ月前」、右端に評価(★)を出します。公開日は何年何ヶ月前だけを出し、
  マウスを載せると `公開日 2023/04/05` のように年月日が出ます。1ヶ月未満は「今月」、未来の日付は「発売前」です。
  公開日が無いときは再生回数だけです。v3.12.0 までは評価・フォルダ名・再生回数と公開日を3行に分けていました。
- **出演者**は、その下(タグの上)に1行で並べ、入りきらなければ折り返します(v3.15.0。v3.14.0 までは詳細欄に縦長のカード)。
  - 1人ずつ、丸い画像・名前・出演時の年齢(`25歳10ヶ月`)を、タグと同じ高さの枠に入れます。どこを押しても出演者ページを開きます(中クリックで新しいタブ)
  - 年齢は公開日(無ければ動画の日付)の時点です。誕生日が無ければ年齢を出さず、画像が無ければ人の形のアイコンにします
  - 色はテーマの色(`--bg-secondary` など)から取ります。ダークモードでは背景を `--bg-tertiary` にします
  - v3.14.0 までの、名前からの検索と除外のボタンは無くしました。出演している動画は出演者ページの関連動画で見られ、
    検索結果は検索画面のサイドメニューの「出演者」で絞り込めます
- 詳細欄は、ジャンル・作品紹介の下に2つの欄を置きます。
  - **作品情報**: 公開日・品番・シリーズ名・メーカー・レーベル・作品監督。何も無ければ「詳細情報は未設定です」の案内
  - **ファイル情報**: 場所・動画ファイル名(名前を変えるボタンも)・フォルダ名・長さ・サイズ・前回再生・更新日・登録日。
    本家の詳細欄(長さ・サイズ・日時・場所)の代わりです
- 欄の見出しを押すと折りたたみます。閉じた欄はその端末に覚えます(`localStorage` の `wlext_watch_fold`)。
  シアターモードと標準モードで同じです(標準モードでは右の情報欄の「情報」に出ます)。
- 実装: 1行の部分は `client/src/pages/WatchPage.jsx`(`.wlext-watch-subrow`)。出演者は `ExtWatchMeta.jsx` の `ExtPerformerPills`(`.wlext-pill`)、作品情報は `ExtMetaBlock`、
  ファイル情報は `ExtFileInfo`、折りたたみは `ExtFoldBox`。公開日は動画の API が `ext_release_date` で返し、詳細情報を保存したときは
  `client/src/utils/videoMeta.js` が `wlext-meta-updated` で知らせます。

## 作品の URL
動画ごとに1つ、作品のページの URL を持ちます(列 `ext_video_meta.url`。v3.15.0)。
- 「詳細情報を編集」の「URL」に入れます。空にして保存すると消えます。使えるのは http と https だけで、スキームが無ければ `https://` を補います。
  `javascript:` などは画面で止め、サーバーでも 400 で断ります。
- 一括操作とリスト表示の「⋮」の「詳細情報編集」にも「URL」の欄があります(v3.15.1)。入れたときだけ、選んだ動画すべてを上書きします。
  空欄なら今の値を残すので、一括では消せません。使えない URL は画面で止め、サーバー(`routes/bulk.js` の `meta`)もほかの項目を含めて何も書かずに 400 で断ります。
- 検索は `@url:none`(未設定)と `@url:any`(設定あり)だけで、値では引きません(v3.15.1)。サイドメニューのいちばん下の「URL」にも同じ2つを出します。
- 動画ページのタイトルの後ろに、リンクを出します。押すと新しいタブで開き、マウスを載せるとサイト名と URL が出ます。検索結果には出しません。
  - 動画の販売・情報サイト(FANZA・MGS・DUGA・SOD・FC2・FC2DB・無修正系の各サイトなど)は、フィルムのアイコンにサイト名を添えます
  - それ以外は出演者の関連URLと同じアイコン(X・YouTube など・地球儀)です
  - タイトルの文字を選んで検索ワードに足すとき、リンクの文字は入りません(`user-select: none`)
- FANZA の商品検索 API の `URL`(作品のページ。アフィリエイト用の `affiliateURL` ではない)を、動画情報の確認画面の「URL」の行で入れます。
  一括取得では空のときだけ入れます。反映は空でないときだけ書き、空なら今の値を残します。
- URL を送らない保存(評価の保存など)では、今の値を残します。バックアップの書き出しと取り込みにも入ります。
- 実装: 表示は `ExtWatchMeta.jsx` の `ExtTitleUrl`、入力は `ExtMetaEdit.jsx`(1本ずつは `ExtMetaEditDialog`、一括は `ExtBulkMetaDialog`)、サイトの見分けは `server/ext/perfurl.mjs` の `urlKind`
  (動画のサイトは `site: true`)。API は `GET`/`PUT /ext/api/video/:id/meta` の `url`(PUT は文字列のときだけ書く)と、`POST /ext/api/dmm/apply` の `item.url`、`POST /ext/api/bulk/meta` の `meta.url`。

## 作品紹介
動画ごとの紹介文です(列 `ext_video_meta.summary`)。
- 「詳細情報を編集」の「作品紹介」に書きます。空にして保存すると消えます。
- 動画ページのジャンルの下(出演者の上)に出します。最初は2行だけで、本文か見出しを押すと全文を開き、見出しで閉じます。
  開閉は覚えません。標準モードでは、右の情報欄ではなくタイトルの下に出します(「動画ページの標準モード」)。
- 改行と、一部のタグを使えます。表示は HTML として埋め込まず、ブラウザの DOMParser で読んで、許可したタグだけを組み直します。
  - 許可するタグ: 改行・段落・太字・斜体・下線・取り消し線・箇条書き・リンク。属性はすべて捨てます(リンクの `href` だけ、http/https に限って残す)
  - `script`・`style`・`iframe` などは中身ごと捨て、それ以外の知らないタグは外して中の文字だけを残します
  - タグの無い文は、改行をそのまま改行として出します
- 動画情報の確認画面は、取得元が紹介文(`item.summary`)を返したときだけ「作品紹介」の行を出します。FANZA の商品検索 API は
  紹介文を返さないので、FANZA の検索・一括取得・スキャン後の自動取得では入りません。反映は空でないときだけ書き、空なら今の値を残します。
- 作品紹介を送らない保存(評価の保存など)では、今の値を残します。バックアップの書き出しと取り込みにも入ります。キーワード検索の対象にはしません。
- 実装: 表示は `ExtWatchMeta.jsx` の `ExtSummary` と `client/src/utils/richText.js`、入力は `ExtMetaEdit.jsx`。
  API は `GET`/`PUT /ext/api/video/:id/meta` の `summary`(PUT は文字列のときだけ書く)と、`POST /ext/api/dmm/apply` の `item.summary`。

## メタデータ置換
設定画面の本家「タグ置換」を「**メタデータ置換**」に差し替え、タグ以外のメタデータも一括置換できるようにします。
- 置換できる種別: **タグ / ジャンル / 出演者 / シリーズ名 / メーカー / レーベル**。
- **完全一致のみ**置換します(部分一致では置換しません)。置換前に確認ダイアログが出ます。
- タグは本家と同じ保存形式(前後を改行で囲む)を扱い、**本家のプリセットと拡張のグループレイアウト**も追従します
  (グループ見出しの `# 名前` は置換対象外)。
- 出演者は出演者マスタの名前を変更します。動画側は出演者IDで持っているのでそのまま追従します。
  置換後の名前が既に登録済みのときはエラーにします(統合は出演者ページで行ってください)。
- 本体の「タグ置換」の代わりに、同じ位置へ同じ見た目で置きます。
- 実装: `server/ext/routes/replace.js`、画面は `client/src/components/ExtSettingsParts.jsx` の `ExtMetaReplace`(管理画面 `SettingsPage.jsx` が置く)、
  API `GET /ext/api/metadata/replace-kinds`, `POST /ext/api/metadata/replace`。

## 一覧ページの一括削除
シリーズ一覧・出演者一覧・タグ一覧で、選んだ項目を全動画のメタデータから取り除きます。
操作と見た目は検索結果の一括操作(選択モード)と同じです。
- 右下のボタンで選択モードに入り、カードをクリックして選択します。「表示中をすべて選択」「選択をすべて解除」も同じ位置です。
- 1件以上選ぶと「⋮」が出て、そこから削除します。**削除する名前の一覧と件数を確認ダイアログで表示**します。
- 消えるのはメタデータの値だけで、**動画そのものは削除しません**。
  - シリーズ: 動画のシリーズ名を空にします。
  - タグ: 本家 `metadata.tags` から取り除き、**本家のプリセットと拡張のグループレイアウト**からも消します
    (グループ見出しの `# 名前` は対象外)。
  - 出演者: 動画側の紐づけを外し、出演者マスタからも削除します(0本の出演者が一覧に残らないようにするため)。
- 実装: `client/src/components/ExtListParts.jsx`(`ExtListFabs` と一括削除のメニュー・確認)、`routes/replace.js`、API `POST /ext/api/metadata/delete`。

## ファイル名からの品番設定
スキャンが終わったら、品番が空の動画にファイル名から品番を入れます。入っている品番は変えません(手で直した値を残すため)。
検索結果の一括操作とリスト表示の「⋮」の「品番をファイル名から設定」でも、選んだ動画に同じように入れられます。
- 基本の形: 拡張子を除いた名前が `英字-数字` なら、それが品番です。数字のうしろの英字1文字(分割ディスクの A/B/C など)は残し、
  末尾の `_数字`(ファイル分割の連番)は落とします。例: `ABC-123.mp4`・`ABC-123_2.mp4` → `ABC-123`、`ABC-123A.mp4` → `ABC-123A`。
- 基本の形に合わないときは、配信サイトごとの形を探します: FC2(`FC2-PPV-1234567` → `FC2-1234567`)・HEYZO・HeyDouga・KIN8・MYWIFE・
  C0930/H0930/H4610・無修正の日付形(`010120_001` など。月日として成り立つものだけ)・Tokyo-Hot(`n1234` など)・
  数字で始まる素人系(`300MIUM-123`)・品番のうしろに空白とタイトルが続く名前(`ABC-123 タイトル.mp4`)。
  どれも形を絞ってあるので、普通の名前(`my-holiday-video.mp4` など)は拾いません。
- 同じ内容の重複ファイルは1本として扱い、どれか1つのファイル名が形に合えばそれを使います。
- 実装: `server/ext/modelno.js`(規則の自己チェックは `node server/ext/modelno.js`)。スキャンのあとは `server/ext/index.js` が
  本体の `POST /api/scan` の応答の直前に入れます。メニューからは `POST /ext/api/model-no/bulk`(`client/src/components/ExtVideoMenu.jsx`)。

## DMM(FANZA) 商品検索によるメタデータ自動設定
各動画ページの右下「動画情報を検索」ボタンから、品番で FANZA 商品情報を検索しメタデータへ自動設定します。
1. 管理画面の「DMM(FANZA) 商品検索API」に API ID とアフィリエイトID を登録（各自の DMM アカウントで取得）。
   ID の表示と変更は、サーバーを動かしている PC からだけ行えます（「PC からだけ行える操作」）。
2. 動画ページで「動画情報を検索」を押すと、品番(model_no)で検索。品番未設定ならエラー。
3. 結果が1件ならプレビュー → 「設定する」で反映。複数なら選択 → プレビュー → 反映。0件なら通知。
   複数のときに品番の末尾で1つに絞れた商品は、先頭に置いて「品番が一致」の印を付けます(v3.15.1。下の「末尾の英字で絞る」)。
4. 反映内容: title→表示動画名 / date→公開日 / genre→ジャンル / series→シリーズ名 /
   maker→メーカー / actress→出演者(自動作成) / director→作品監督 / label→レーベル / URL→URL。
   (品番・評価は維持。カバー画像が未設定なら商品画像を取得して設定)
- **確認画面で項目ごとにチェックを外せます**。「現在の値 → 新しい値」を並べ、チェックを付けた項目だけを
  設定します(既定は全部オン)。カバー画像の取得も同じように選べます。
- 項目が2つ以上あるときは、先頭に**「すべて」の行**を出し、項目とカバー画像のチェックをまとめて付け外しします。
  一部だけ付いているときは中間の印になり、「6 / 7 項目を設定」のように数を出します。ファイル名の行は含めません
  (名前を変えるかは、設定と個別のチェックで決めます。「ファイル名の変更」)。
- 取得元が紹介文を返したときは「作品紹介」の行も出します(「作品紹介」の節)。
- **ジャンルだけは上書きせず、既存 + FANZA の和集合**にします(重複は除外・既存の並び順は保持)。
- **FANZA 側が空だった項目は、既存の値をそのまま残します**。確認画面には値のある項目だけを表示するので、
  そこに出ていない項目は変更しません(出演者情報を持たない商品を反映して、手で入れた出演者が消える問題への対応)。
- **レーベルが `----` のときは空として扱います**(FANZA はレーベルなしをこの名前で返すことがあります)。
- 商品の探し方は、売り場(動画→通販)ごとに次の順で試し、最初に見つかったものを使います。
  1. 品番をそのままキーワード検索 → 2. cid(`aarm00004` 形式)で厳密一致 → 3. cid 形の文字列をキーワード検索
  3 は content_id に接頭辞が付く作品のための逃げ道です(例: `TOTTE-283` の content_id は `1totte00283` で、
  1 と 2 のどちらでも 0 件になります)。
- **取得した商品は品番で照合し、一致するものだけを候補にします**。FANZA のキーワード検索は部分一致なので、
  そのままでは品番の前に別の英字が付いた作品まで拾ってしまいます(`AP-147` で `SLAP-147` が返るなど)。
  content_id 側の英字と数字を品番と突き合わせ、英字の直前が英字でないこと・数字がゼロ埋めの違いを除いて
  同じこと・その数字の後ろに数字が続かないこと(`CLUB-051` が `CLUB-513` に当たらない)を確かめます。
- **末尾の英字で絞る**(v3.15.1): 上の照合は content_id の数字の後ろ(分割販売の a・b・c、別版の z・ai など)を見ないので、
  同じ品番の商品が複数残ることがあります。そのときは品番の数字の後ろの英字(`DANDY-681A`・`NHDTB-301-C` の A・C。無ければ空)と、
  content_id の数字の後ろの英字が同じ商品を探し、1つだけなら先頭に置いて `best: true` を付けます(`dmm.js` の `markBest`)。
  2つ以上か0なら付けません(例: `NHDTB-396` に `1nhdtb00396` と `1nhdtb00396z` があれば前者。`NHDTB-218` のように `a` と `b` しか無ければ付けない)。

### 一括取得
検索結果の一括操作(選択モード)とリスト表示の「⋮」の「動画情報を取得」で、選んだ動画をまとめて取得します。
- 1本ずつ順に品番で検索し、品番の一致する商品が**1つだけのとき(複数でも `best` の付いたものがあればそれ)に、空の項目だけを埋めます**。今の値がある項目は変えません
  (1本ずつの「動画情報を検索」は、確認画面で選んだ項目を上書きします)。カバー画像は未設定のときだけ取得します。
- **取得する項目を選べます**(v3.15.0)。「取得する」の前に、表示動画名・公開日・出演者・ジャンル・シリーズ名・メーカー・レーベル・
  作品監督・URL・カバー画像のチェックと「すべて」の行を出します。最初はすべてに付いています(それまでと同じ動き)。選んだ項目は覚えません。
  - 選んだ項目のうち、空のものだけを埋めます。選んでいない項目は、空でも埋めません
  - 選んだ項目がすべて埋まっている動画は、FANZA に問い合わせずに飛ばし、「値がある N本」と数えます
    (カバー画像があるかは、詳細情報の API の `has_cover` で見ます)
  - ファイル名をルールで変える設定がオンでも、名前に使う項目(表示動画名・公開日・出演者・メーカー・レーベル・シリーズ名)を
    埋めたときだけ変えます。URL やジャンルだけを埋めた動画の名前は変えません
  - スキャン後の自動取得は、すべての項目で取得します
  - すべての動画に URL を入れるときは、検索結果を1ページ100件にして、ページごとに「表示中をすべて選択」を押してから取得します
    (選択はページを移っても残ります)
- 見つからない・候補が複数・品番なし・失敗の動画は飛ばし、最後に一覧で出します。一覧の動画は別のタブで開くので、
  一覧を残したまま1本ずつ直せます。
- **候補が複数で飛ばした動画は、一覧の「選ぶ」で候補(画像・タイトル・content_id・発売日・レーベル)を開き、押した商品で埋めます**(v3.15.1)。
  埋め方は自動のときと同じで、選んだ項目の空のものだけです。同じ品番で飛ばした動画(パート)もまとめて埋め、一覧から外します。
  パートごとの商品は、その動画の検索結果から同じ content_id のものを使います(検索結果は動画ごとに作るため)。「選ぶ」は取得中は出しません。
- 失敗した動画は、最後に3秒おいてもう1回だけやり直します。API ID が未設定ならその場で止めます。
- 取得中は「N / M 本」と進み具合を出し、「中止」(✕・Esc も)で今の1本を終えてから止まります。
- 同じ品番のパートは、サーバーが10分だけ結果を控えるので、FANZA への問い合わせは品番ごとに1回です(`dmm.js` の `findItemsCached`)。
- 実装: `client/src/components/ExtMetaSearch.jsx` の `BulkMetaFetchDialog`(メニューは `ExtVideoMenu.jsx`)。検索は 1本ずつのときと
  同じ `window.WLExt.dmmSearch` を通し、反映も同じ `POST /ext/api/dmm/apply` です(今の値がある項目は空にして送る)。

### スキャン後の自動取得
管理画面でスキャンが終わると、「動画情報を取得」の画面が開き、そのまま取得を始めます。
- 対象は、そのスキャンで増えた動画(スキャン前の最大の id より後の行)のうち、品番があってメーカーが空の動画です。
  ファイル名を変えた動画も増えた動画として数えますが、詳細情報が残っていればメーカーが入っているので対象になりません。
- 取り方は一括取得と同じで、空の項目だけを埋めます。DMM の API ID とアフィリエイトID が登録されているときだけ動きます。
- 管理画面の「DMM(FANZA) 商品検索API」の「スキャンのあと、増えた動画の動画情報を自動で取得する」で止められます(既定はオン。
  設定 `ext_dmm_auto_fetch` は全ライブラリ共通)。
- 実装: `server/ext/index.js` の `/api/scan` のフックが、対象の id を応答の `ext_fetch_ids` に入れます。管理画面(本体の
  `client/src/pages/SettingsPage.jsx`)がそれを `BulkMetaFetchDialog` に `auto` 付きで渡します。

### 動画情報が未取得の動画
「DMM(FANZA) 商品検索API」の欄の「動画情報が未取得の動画を検索」で、品番があってメーカーが空の動画を検索します
(`@model:any maker:none`)。直した動画は検索結果から外れます。
- 検索の値 `any` は「設定あり」で、`none`(未設定)を使える項目(maker・model・series・label・release・director・genre・performer・tag・url)に使えます。
- 項目を2つ以上並べるときは、`@` を先頭にだけ付けます(2つ目以降の `@` はキーワードとして読まれます)。

## 出演者タグの自動付与
管理画面の「出演者タグ 自動付与ルール」で、条件に合う出演者へ自動でタグを付けます。
- ルール = 条件(フィールド・演算子・値) → 付与タグ。例: 身長 ≧ 170 → 高身長。
- フィールド: 身長/体重/バスト/ウェスト/ヒップ/カップ数/評価/年齢/血液型。
  年齢は誕生日から自動算出。カップ数や血液型は文字比較(D≧C など)。
- **出演者側にその項目が登録されていない場合、そのルールは不一致として扱います**(どの演算子でも付与しません)。
  未登録を空文字として比較していたため、カップ数の「≦ D」や「≠ F」が未登録の出演者全員に当たっていた問題への対応です。
  評価は未評価でも 0 が入るため、関連動画の平均評価と同じく未登録として扱います。
- 「適用」で全出演者へ一括付与(冪等)。
- 「同期」チェック時は、条件に合わない出演者から「ルールのタグ」を外します  (ルールに無いタグや手動タグはそのまま)。

## 出演者一覧 (/performers)
ホーム画面の「出演者一覧」から開きます。
- **各画像の右上に関連動画数**をバッジで表示。
- ソート: 評価 / 出演数（関連動画数。評価の右） / ふりがな / 身長 / 体重 / バスト / カップ数 / ウェスト / ヒップ / 年齢 。**選択したソートはブラウザに保存され、ページを離れても次回表示時に復元されます**。

## 出演者ページ
`/performer/:id`。氏名・ふりがな・誕生日・スリーサイズ・別名・出演者タグ等の編集、
画像アップロード＋正方形トリミング、関連動画・関連スクリーンショットを表示します。
- 動画ページの出演者を押すと開きます。
- **関連動画の件数**を「関連動画（N）」と見出しに表示します（N は出演している動画数）。
- ライブラリが複数あるときは、見出しの下に**ほかのライブラリの本数**を「ほかのライブラリ: 名前 N本」と出します。
  数え方は関連動画と同じ(ファイルのある動画だけ)。0本のライブラリは出さず、どこにも無ければ行ごと出しません。
  ほかのライブラリの動画は切り替えないと開けないので、本数だけです。
  API `GET /ext/api/performer/:id` の `other_libraries`(`[{ name, count }]`。`server/ext/library.js` の `performerCountsElsewhere`)。
- **関連スクリーンショット**は関連動画と同じサムネイルサイズで表示します。見出し右の
  「最近」「ランダム」で切り替え可能。
- 関連スクリーンショットの枚数は、**8枚以上で行がそろう最小の数**（列の数の倍数）です。列の数は画面の幅で決まり
  （例: 5列なら10枚、4列なら8枚、3列なら9枚、スマホの1列なら8枚）、幅を変えると数え直します。
  出演者のスクリーンショットがその数に足りなければ、ある分を左詰めで出します。
  サーバーからは24枚まで取っておき、幅を変えても取り直しません（ランダムも引き直しません）。
- **関連URL**: 評価の下に、公式サイトや SNS などの URL を種類のアイコンで右寄せに並べます(入りきらなければ折り返す)。
  押すと新しいタブで開き、マウスを載せると種類と URL が出ます。
  - アイコンはドメインで決めます: X(x.com・twitter.com)・Instagram・TikTok・YouTube・Wikipedia(本の形)・ブログ(ameblo・note など)・
    動画のサイト(FANZA・MGS など。フィルムの形。v3.15.0)・それ以外(地球儀)
  - 横の鉛筆(URL が無ければ「＋関連URL」)で編集します。入力欄は最初は1つで、「URL を追加」で増やし、×で消します
  - 使えるのは http と https の URL だけです。スキームが無ければ `https://` を補い、同じ URL は1つにまとめます。
    `javascript:` などは画面で止め、サーバーでも捨てます
  - 保存先は列 `ext_performers.urls`(改行区切り。出演者と同じく全ライブラリ共通)。URL を送らない保存では今の値を残します。
    バックアップにも入ります
  - 実装: URL の扱いは `server/ext/perfurl.mjs`(`normalizeUrl`・`urlKind`。サーバーと本体の画面で共用、`node server/ext/perfurl.mjs` で自己チェック)
- 実装: `client/src/pages/PerformerPage.jsx`(関連スクリーンショットは `ShotGrid`、関連URL は `PerfLinks`・`UrlsDialog`)、API `GET /ext/api/performer/:id/screenshots?limit=`(既定8・最大48、`&sort=random`)。

## メーカー一覧 (/makers)
ホーム画面と右上メニューの「メーカー一覧」から開きます。動画に設定されたメーカーを横長のリストで表示します。
- **メーカー画像**は 1:1。既定はメーカー名から生成した無地背景に名前を表示し、画像を登録すると差し替わります。
  右上に動画本数、右下の編集ボタンから画像を登録します。そのまま登録すると画像全体を中央に表示し、
  拡大すると正方形に切り取れます。GIF / APNG / WebP の**アニメーション画像は動いたまま**保存します
  (元の画像と表示範囲を保存し、表示するときに範囲を当てます)。
- 画像とメーカー名のクリックで、そのメーカーを検索(`@maker:"名前"`)。
- **平均評価**はそのメーカーの動画の評価の平均(評価0=未評価は計算から除外。全て未評価なら「評価なし」)。
- **キャッチコピー**は名前の下。クリックでその場で編集でき、Enter で保存・Esc で取り消しです。
- **TOP10タグ**はそのメーカーの動画に付いたタグを多い順に10個。クリックでメーカーとタグの AND 検索
  (`@maker:"名前" tag:"タグ"`)。
- **レーベル一覧**は開閉式で、`レーベル名(本数)` を本数の多い順に表示します。クリックでそのレーベルを検索。
  レーベル未設定の作品は **「レーベルなし」として本数によらず末尾**に置き、クリックすると
  そのメーカーのレーベル未設定の作品を検索します(`@maker:"名前" label:none`)。
- **FANZAリンク**は右下。リストページURLが登録されているときだけ表示し、新しいタブで開きます。
  **公式サイトURL**を登録すると、公式サイトへのリンクも並べます。
- ソート: メーカー名 / 動画本数 / 評価。**選択したソートはブラウザに保存され、ページを離れても次回表示時に復元されます**。
- 右端の「⋮」から**メーカー情報編集**(ふりがな・キャッチコピー・リストページURL・公式サイトURL)と、**メーカー情報取得**を実行できます。

### メーカー情報取得（DMM メーカー検索API）
「⋮」→「メーカー情報取得」で、FANZA から**読み仮名**と**リストページURL**を取得します。
API ID とアフィリエイトID は DMM 商品検索と同じ設定を使います。
- メーカー名が完全一致すれば確認画面へ。一致しなければ**候補の一覧**を出すので、選ぶか、
  名前を変えて検索し直してください。設定するかどうかは確認画面で決めます。
- **メーカー名そのものは変更しません**(動画側のメタデータなので、名前を変えるときはメタデータ置換を使います)。
- MakerSearch API はキーワード検索を持たず `floor_id` が必須のため、FANZA 動画のメーカーを全件取得して
  サーバー側に1時間キャッシュし、名前の突き合わせは拡張側で行います(初回だけ数秒かかります)。
- メーカー情報は `ext_makers` テーブルに保存し、バックアップの対象にも含めています。
  全ライブラリ共通で、既定のライブラリの DB に置きます(追加ライブラリにあった分は起動時にまとめます)。

## カバー画像
動画と同名の画像を指定フォルダから自動割り当てし、動画ページのスクリーンショット欄の先頭に表示（クリックで拡大）。
- 例: 動画 `AAA.mp4` に対し、フォルダ内の `AAA.jpg`（または .png/.webp 等）を自動表示。
- 管理画面の「カバー画像」でフォルダを指定して保存。
- DMM 商品検索で取得したカバーは `ext_video_cover` テーブルに保存（フォルダ未設定でも表示可）。
- 両方あるときは**フォルダの画像を優先**します（自分で置いた画像を DMM のカバーより先に出す）。
- 実装: カードは `client/src/components/ExtWatchParts.jsx` の `CoverCard`(動画ページ `WatchPage.jsx` がスクリーンショットの欄の先頭に置く。拡大は `ExtImageDialogs.jsx` の `ExtLightbox`)。DMM の情報を反映したあとは `ExtMetaSearch.jsx` が `wlext-cover-refresh` を投げて取り直させます。

## 検索結果のサムネイル切替（スクリーンショット／ジャケット）
検索画面上部の表示形式ボタン(グリッド/リスト等)の右に、サムネイルの切替ボタンを置きます。
- カメラ: 本家どおりスクリーンショットのサムネイル。画像: カバー画像(ジャケット)を表示。
- カバー画像が無い動画は、ジャケット表示でもスクリーンショットのままです。
- 選んだ状態はブラウザに保存します(端末ごと)。ボタンの見た目は本体の表示形式ボタンと同じです。
- 狭い画面で表示件数ボタンがはみ出さないよう、表示設定の行を折り返します。
- 実装: 本体の検索画面 `client/src/pages/SearchPage.jsx`(ボタン)と `client/src/components/VideoList.jsx` の `useCoverThumb`(カードの画像)。

## 検索結果のリスト表示（シリーズ・監督・ジャンル）
検索結果をリスト表示にしたとき、拡張メタデータの一部をカードに並べます。グリッド表示・ポスター表示では出しません。
- **シリーズ名**: 評価の行の先頭(評価の左)。行幅の半分を超える名前は末尾を「…」にします(全体はマウスを乗せたときのツールチップに出ます)。
- **出演者と監督**: 評価の行の下に「出演者：A、B　監督：X」の形で並べます。どちらか片方だけでも出します。
- **ジャンル**: タグの行の先頭に、動画ページのジャンルと同じ見た目で並べ、タグとの間を「│」で区切ります。
  行に収まらないときはタグの側(末尾)から削って「…」を付け、マウスを乗せるとジャンルとタグを全部表示します。
- シリーズ名・監督・ジャンルを押すとその条件で検索します(`@series:"…"` / `@director:"…"` / `@genre:"…"`)。出演者を押すと出演者ページを開きます。
- 値は一覧 API (`/api/videos`) が一緒に返します(`routes/search.js` の `withCardFields`。メーカー・シリーズ・ジャンル・監督・出演者)。
- 実装: `client/src/components/ExtCardParts.jsx`(検索画面のカードだけに出す。サムネのメーカー名とフォルダ名、評価の行も同じファイル)。
  見た目は `womanlive-ext.css` のクラス(`.wlext-maker-ov` / `.wlext-folder-ov` / `.wlext-card-meta` ほか)。
  評価の行の末尾にブックマークボタンとスクショ数(`ExtCardBadges`。検索画面以外のカードにも出す)。

## 同じ品番の動画をまとめて表示
検索画面で、品番(拡張メタデータ)が同じ動画を1枚のカードにまとめます。パート分割された作品向けです。
- 切替ボタンは表示形式ボタンの並び(サムネイル切替の右)。**既定はまとめる表示**で、状態はブラウザに保存します。
- カードを押すと先頭のパート(ファイル名の自然順)を再生します。サムネイル左上の **「N本」** を押すと
  パートの一覧が開き、選んだ動画を再生します。カード名からは末尾の `_数字` を外して表示します。
- カードの並び順は、グループの中で今のソートの一番前に来るパートの位置です。条件に一部のパートだけが
  当たるときは、当たったパートだけでまとめます。
- 件数と絞り込み(サイドメニュー)の件数は、まとめた後の数で数えます。本家のカテゴリー欄の件数はファイル数のままです。
- 一括操作・リスト表示の「⋮」・グリッドの「⋮」のタグ付け外しは、**まとめた全パート**に効きます。
- プレビュー中に出る本家のミュートボタンは、「N本」の下へずらします。ポスター表示では「N本」を左下
  (シークバーとファイル名の帯の上)に置きます。
- 品番の無い動画はまとめません。
- 実装: まとめるのは `routes/search.js` の `groupedVideos`。トグルは検索画面(`SearchPage.jsx`)にあり、一覧と件数の要求に
  `group=1` を付けます。「N本」はカード(`VideoList.jsx`)が `ext_group_count` から出し、押したときの一覧は
  `client/src/components/ExtVideoRow.jsx` の `ExtGroupMembers` です。カードの名前からパート番号を外すのは `routes/search.js` が行います。

## 検索結果のサイドメニュー（絞り込み）
検索結果の左側に、今の結果をさらに絞り込むためのサイドメニューを出します。
- **画面左上の「絞り込み」ボタン**で開閉します。位置は固定で、スクロールしても動きません。
  既定は **PC=開く / モバイル=閉じる**(`(max-width: 900px), (pointer: coarse)` で判定)で、
  切り替えた状態はその端末に記憶します。狭い画面では一覧を押し出さず**重ねて表示**し、
  背景をタップすると閉じます。閉じている間はパネルを作らないので、候補の取得も走りません。
- 一番上が **評価** の範囲スライダー。0〜5 の点の両端をドラッグ(またはクリック)して範囲を決めます。
  動かしている間は数値表示だけ変わり、離した時点で検索し直します。検索条件は `rating` トークン2つ
  (`@rating:">=2" rating:"<=4"`)で、全域(0〜5)にすると `rating` を外します。下限0は未評価も含みます。
  (本家のソートボタン群にあった ★1〜★5 の絞り込みはここへ移しました)
- その下が **再生時間** の範囲スライダー。動かし方は評価と同じで、目盛りは 0・15・30・45・60・90・120・180・240分です
  (等間隔ではありません。短い動画の多いライブラリでも長い動画の多いライブラリでも使えるように)。右端の240は上限なしです。
  検索条件は `@duration:">=30" duration:"<=60"`(分)。下限0は長さのわからない動画も含みます。
  目盛りに無い値を手で書いたときは、それを含む広めの範囲として表示します。キーワードの `>30`・`<10` とは別の条件です。
- 続けて **視聴 / タグ / ジャンル / メーカー / 出演者 / シリーズ / URL** の順。各項目は**今の検索結果**に対する
  件数の多い順に並べ、右端に件数を出します。
- **視聴**は「未再生」(再生回数0)と「視聴途中」(60秒以上見て、終わりの1割より前で止めた動画)、
  「次のパート」(同じ品番でファイル名の順に1つ前のパートを見終えた、未再生の動画。見終えた＝再生済みで視聴途中でない)です。
  検索語は `@play:unwatched` / `@play:partial` / `@play:next`。
- タグからシリーズまでの各項目は、先頭に**「未設定」**(その項目が空の動画)を出します。検索語は `@tag:none` のように
  値を `none` にします。監督・レーベル・品番・公開日も同じ書き方で使えます(`@release:none`)。
- いちばん下の **URL** は「未設定」と「設定あり」の2つだけです(`@url:none` / `@url:any`。v3.15.1)。
- **上位5件を表示し、残りは「すべて表示（他 N 件）」で開閉**します(出演者は数百件になり得るので、
  開いたときに初めて描画します)。
- クリックでその条件を今の検索に足します。**適用中の項目はアクセント色**になり、もう一度押すと外れます。
  絞り込むたびに候補と件数も計算し直します。
- 出演者だけは検索が id 指定(`@performer:ID`)なので、表示は氏名・検索は id を使います。
- **検索結果画面では常に出ます**。キーワード検索(本家のタグバッジ・年月リンクからの遷移も含む)でも
  表示し、絞り込みを足しても**キーワードは消えません**。項目条件とキーワードは
  `@maker:"X" 温泉` のように1つの検索語として扱い、AND で絞り込みます。
  絞り込みを全部外すと、`@` の付かない元のキーワード検索に戻ります。
- **本家のフォルダ絞り込み(カテゴリー)と再生履歴ソートも候補の集計に効かせます**。一覧と同じ母集団を
  数えるため、`path` と `sort` も同じ条件で扱います。
- 一覧を右へ寄せる量は「パネルの右端 + 16px」になるよう実測して決めます(狭い画面では 22px で、パネルは一覧に重ねます)。
- 押すと検索画面の中で条件を変えます(ページ全体は読み直しません)。
- 実装: `client/src/components/ExtFacets.jsx`(検索画面 `SearchPage.jsx` が置く。範囲スライダーは `RangeSection`)、`routes/search.js` の `facets`、
  API `GET /ext/api/search/facets?q=...`。キーワードの条件組み立ては `routes/fullsearch.js` の
  `keywordWhere` を項目検索側と共用しています。

検索画面の件数の右の「この条件を保存」で、今の検索に名前を付けて保存します。
- 保存するのは検索語・並び順・カテゴリーのフォルダです。ページ番号と1ページの件数、品番でまとめる表示の切り替えは入れません。

## 検索ワード
動画ページで見つけた語をためておき、検索欄にまとめて貼り付けます。
- **文字を選んで足す**: タイトル・動画ファイル名・作品紹介の文字を選ぶと、選んだ範囲の下(画面の下に収まらなければ上)に
  「＋ 検索ワード」のボタンが出ます。押すと選んだ文字をためます。日本語は空白で語を区切らないので、どこで切るかは選ぶ人が決めます
  (ブラウザの単語の区切り `Intl.Segmenter` を実データで試したところ、人名や「中出し」のような複合語が割れたので使っていません)。
  欄の外まで選んだときは、選び始めた欄の中だけを使います。100文字を超える選択にはボタンを出しません。
  閉じた作品紹介は、文字を選んで離したときには開きません(選ばずに押すと開きます)。
- **ファイル名の語**: 動画ファイル名に空白(半角・全角)があれば、拡張子を除いた名前を空白で区切った語を押せるようにします。
  押すとためて、ためた語には下線が付き、もう一度押すと外れます。中クリックはその語だけの検索を新しいタブで開きます。
  最後の語の末尾のパート番号(`_2` など)は語にしません。
- **貼り付け**: ためた語があるときだけ、検索欄の右(？の右)にボタンを出し、右上に語の数を出します。押すと検索欄の末尾に
  空白区切りで足して検索欄にカーソルを置き、ためた語は空にします。マウスを載せると、ためている語の一覧が出ます。
- **語の形**: 空白・改行は1つの空白にし、`"` と先頭の `>` `<` は外します(キーワード検索は `"` を逃がせず、`>` `<` は引用符で
  囲んでも日付・再生時間の指定と読まれるため)。空白を含む語と、`-` `!` `~` `@` で始まる語、`OR` は `"…"` で囲んで、ふつうの語として探します。
  同じ語は1つにまとめ、50個まで残します。
- 保存先はブラウザの `localStorage`(`wlext_search_words`)です。同じブラウザのタブどうしで共有し、ほかのタブの変更は `storage` イベントで
  読み直します。OS のクリップボードは使いません(LAN の端末ではブラウザが読み書きを許さないことがあり、いつものコピーの中身も上書きしないため)。
- 実装: `client/src/utils/searchWords.js`(ためる・整える・囲む・`useSearchWords`)、`client/src/components/ExtSearchWords.jsx`
  (`ExtPickWord`・`ExtFileWords`・`ExtPasteWords`)。選べる欄は `data-wlext-pick` の付いた要素(`WatchPage.jsx` のタイトル、
  `ExtWatchMeta.jsx` の動画ファイル名と作品紹介)。貼り付けのボタンは `Navbar.jsx`。

## 動画ページの標準モード
動画ページに、プレイヤーの右に情報欄を置く **標準モード** を追加します。今までの配置は **シアターモード** です。
- 切り替えはプレイヤー下の「プレイヤー設定」ボタンの右。説明は今のモードに応じて「シアターモードへ変更」/
  「標準モードへ変更」になります。**既定はシアターモード**で、選んだモードはブラウザに保存します。
- 標準モードは、ヘッダー・プレイヤー・右の情報欄・タイトルと再生回数の欄だけを、画面に収まる大きさで表示します
  (ページはスクロールしません)。情報欄はその中だけがスクロールします。
- プレイヤーの下の欄(タイトル・タグ・作品紹介)は画面の下端までの高さで、はみ出す分はその欄の中でスクロールします。
  作品紹介を開いて長くなっても、プレイヤーは画面の上に出たままです。プレイヤーの大きさはタイトルの欄までで決め、
  欄の中をスクロールしても変わりません。動画を移ると欄は先頭に戻ります。
- 作品紹介は、右の情報欄ではなくタイトルの下に出します(`WatchPage.jsx` がもう1つ置き、CSS の `body.wlext-std` で出し分ける)。
- 情報欄の項目は上の「＜」「＞」か項目名で切り替えます。
  - **サムネイル**: カバー画像を元の縦横比のまま欄の幅いっぱいに出し、その下にスクリーンショットを並べます(表示サイズ変更も可)。
  - **同じシリーズ**: 同じ品番のパートを先頭に、続けて同じシリーズの作品を公開日の古い順に並べます
    (品番ごとに1行・「N本」付き)。今の作品には印が付きます。見出しの「同じ品番」を押すとその品番で、
    シリーズ名を押すとそのシリーズで検索します。
  - **関連**: 関連動画の一覧。本家が次に自動再生する動画に「次に再生」と出します。
  - **情報**: タグ・詳細情報などシアターモードで下に出ている情報。
  - **イメージリスト**: イメージリストを開いている間だけ出て、自動でこの項目に切り替わります。
- 右下の丸ボタンは、標準モードの間は情報欄の下端に並べます(並びはシアターモードと同じ)。
- 幅 1000px 未満の画面と全画面表示では使わず、切り替えボタンも隠します。
- 実装: 切替・右欄の見出し・大きさは `client/src/components/ExtStandard.jsx`(動画ページ `WatchPage.jsx` が置く。切替ボタンはプレイヤーの
  `renderExtraControls`)。右欄の「同じシリーズ」「関連動画」の一覧は `client/src/components/ExtVideoRow.jsx`
  (`ExtStdSeries`/`ExtStdRelated`。API `GET /ext/api/video/:id/siblings`・`GET /ext/api/videos/brief?ids=`)。
  右欄へ重ねる CSS は `womanlive-ext.css` の `body.wlext-std` の規則で、目印は `WatchPage.jsx` が付ける `data-wlext-std`。

## コマ送り
動画を1コマずつ進める／戻せます。本家のホイール操作（5秒送り）はそのままです。
- **`.`** で1コマ送り、**`,`** で1コマ戻し。再生中に押すと一時停止してから動きます。
  文字入力中や拡張のダイアログを開いている間は反応しません。
- **プレイヤー上で Shift+ホイール**でも同じ操作。下方向で送り、上方向で戻しです。
- **スマホやタブレット**では、一時停止中のプレイヤーに半透明のボタンを重ねます。
  左端で1コマ戻し、中央で再生、右端で1コマ送りです。再生中とマウス操作の端末では表示しません。
  本家の横スワイプ（滑らせた距離で早送り・巻き戻しする操作）はそのまま使えます。
- 操作すると画面上部に、時刻とフレーム番号・フレームレート（例: `▶ 1:40.033 (2999F / 29.97fps)`）を
  1秒ほど表示します。
- フレームレートは ffprobe で取得し、動画ごとに1回だけ調べて以降は使い回します
  （本家は保持していないため。追加テーブルは作りません）。
- **変換再生（トランスコード）の動画はコマ送りできません**。セグメントを取り直す再生方式のためで、
  操作すると1回だけ通知します。ファイルをそのまま再生できる動画（mp4 など大半）が対象です。
- 実装: `client/src/components/ExtWatchParts.jsx` の `FrameStep`(プレイヤー `Player.jsx` が枠の最後に置く)、フレームレートは `server/ext/routes/frame.js`。

## プレイヤーのキー操作
本家のキー(矢印・スペースなど)に次を足しています。文字入力中と、Ctrl・Alt などと一緒に押したときは反応しません。
- **F** 全画面の切り替え / **M** ミュートの切り替え / **K** 再生と一時停止
- **J** 10秒戻る / **L** 10秒進む
- **0〜9** 動画のその割合の位置へ(3 なら 30% の位置)
- **`<`** / **`>`** 再生速度を 0.25 ずつ変える(0.5〜3倍)。変えると画面に速度を出し、プレイヤー設定の速度の欄にもその値が並びます
- **`Shift+←`** / **`Shift+→`** 前・次のスクリーンショットの位置へ(スクリーンショットの無い動画は5秒の移動。「スクリーンショット関連」を参照)
- 実装: `client/src/components/Player.jsx` の keydown(本家の `switch` の `default:`)。

## スクリーンショット関連（枚数表示・ソート・表示サイズ変更）
検索結果カードに、各動画のスクリーンショット枚数を表示し、枚数で並べ替えできます。各動画ページのスクリーンショット欄にスライダーを追加し、表示サイズを変更できます（画像そのもの・解像度は変更しません）。
- フォルダ名の右・ブックマークボタンの左に、単色カメラアイコンでスクリーンショット枚数を表示。
- 検索画面の並び替えに「スクショ数」を追加（押すたびに多い順と少ない順を切り替え）。
- 表示サイズは**80px〜640px**の範囲で変更（既定 160px。16:9 の縦横比を維持）。
- カバー画像（先頭のカバーカード）も同じサイズに追従します。
- 変更したサイズはブラウザに保存され、次回訪問時も引き継がれます。
- **シークバーにスクリーンショットの位置の印**を出します。本家の印はマウスを乗せている間だけ見えましたが、
  v3.7.0 からは乗せていないときも線と同じ太さで出します。
- 動画ページで **`Shift+←` / `Shift+→`** を押すと、前・次のスクリーンショットの位置へ移り、「スクリーンショット 3/12」と出します。
  戻るときは今の位置の1.5秒前より前の印へ移るので、印の位置で続けて押すとその前の印へ戻れます。
  スクリーンショットの無い動画では、本家どおり5秒の移動です。
- 実装: 枚数はカードの `client/src/components/ExtCardParts.jsx` の `ExtCardBadges`(描いたカードの分をまとめて `/ext/api/screenshots/counts` で取る)。
  スライダーは `client/src/components/ExtWatchParts.jsx`(動画ページ `WatchPage.jsx` がスクリーンショットの欄の末尾に置く)。欄に付けた `--wlext-ss-w`/`--wlext-ss-h` を `womanlive-ext.css` がカードとカバーに当てます。
  シークバーの印は本体の `client/src/components/Player/PlayerControls.jsx`、`Shift+←→` は `Player.jsx` の keydown の `jumpShot`。

## 次のパートの自動再生
動画を最後まで見ると、同じ品番の次のパート(`_2` の次は `_3`)を5秒数えてから開きます。

- 最後のパートと、品番の無い動画では出ません。

## モバイルでの「端末に保存」「アプリで開く」
本家の動画ページにある「フォルダーを開く」「アプリで再生」は、**サーバー機**のエクスプローラや
既定プレイヤーを開くもので、`localhost` で見ているときしか表示されません。手元の端末から見ている
ときに使えるよう、**タッチ端末(`(pointer: coarse)`)では次の2つ**を同じ位置に出します。
- **端末に保存**: ブラウザの標準ダウンロードで動画ファイルを保存します
  (`Content-Disposition: attachment`。日本語ファイル名は `filename*` で渡します)。
- **アプリで開く**: OS のアプリへ渡して再生します。Android は `intent:` でアプリ選択に渡し、
  開けるアプリが無ければ元のURLへ戻ります(`browser_fallback_url`)。iOS などは別タブで開くので、
  標準プレイヤーの共有メニューから他アプリへ渡せます。
- 配信は `GET /ext/api/video/:id/file`(`?dl=1` でダウンロード)。本家の `/api/stream/:id` は設定に
  よって変換したストリームを返すので、こちらは**常に元ファイル**をそのまま返します。外部プレイヤーが
  シークできるよう Range に対応しています。
- localhost をタッチ端末で見たときは、本家の2ボタンの代わりに出します。
- 実装: ボタンは `client/src/components/ExtWatchParts.jsx` の `MobileActions`(動画ページ `WatchPage.jsx` がタッチ端末のときだけ「コーデック情報」の箱の後ろに置く)、配信は `server/ext/routes/file.js`。

## ホーム画面
管理画面の「ホーム画面」で、ホームに出すものと行の並びを決めます。ホームのいちばん下の「ホームを編集」から、この項目へ移れます。
- カルーセル(ランダムに15本)とメニューは、出すか隠すかだけを選べます。位置は上のままです。
- 行ごとに、出すかどうか・並び(↑↓)・名前・本数(4本／8本／12本)を変えられます。名前を空にすると、もとの名前になります。
  変えたあとは「保存」で書き込みます。「既定に戻す」は画面の中だけを戻し、「保存」を押すまでは変わりません。
- 組み込みの行は次の7つで、既定で出すのは上の3つです。
  - **最新動画（1ヶ月以内）**: 更新日が1ヶ月以内の動画をランダムに。1本も無いときは、代わりに PICKUP を出します(PICKUP の行を出しているときは代えません)。
  - **続きを見る**: 視聴途中の動画(`@play:partial`)を、最近再生した順に。v3.5.0 までの「予約中」の行と、新しい DB の初期のタグ「予約」はなくしました(今ある「予約」のタグは普通のタグとして残ります)。
  - **最近再生した動画**: 再生した動画を、最近再生した順に。
  - **次のパート**: 前のパートを見終えた未再生のパート(`@play:next`。「検索結果のサイドメニュー」の視聴)を、その品番のパートを最近再生した順に。この並び順(`sort=ext_partplayed_desc`)は検索画面の並び替えの列には出しません。
  - **未再生**・**高評価**(評価4以上)・**PICKUP**(すべての動画): どれもランダムに。
- 「保存した検索を行に足す」で、保存した検索(「保存した検索」の節)を行にできます。行は検索語・並び順・フォルダの写しを持つので、
  もとの保存した検索の名前を変えたり消したりしても、行はそのまま残ります。行は30までです。
- 動画が1本も無い行は出しません。「もっと見る」は同じ条件の検索画面です。ランダムの行は同じ乱数の種を渡すので、ホームと同じ並びの続きが出ます。
- ランダムの並びは5分ごとに変わります(行ごとに種をずらし、同じ動画が並びにくくしています)。
- 保存先は DB の設定 `ext_home_layout` です。ライブラリごとに分かれ、`ext_` で始まるのでバックアップにも入ります。
  保存が無いときは v3.7.0 までと同じ並び(最新動画・続きを見る・最近再生した動画)です。
- 実装: 行を描くのは `client/src/pages/HomePage.jsx`、組み込みの行と既定の並びは `client/src/utils/homeLayout.js`、
  管理画面の項目は `ExtSettingsSections.jsx` の `ExtHomeSettings`。API は `GET`/`PUT /ext/api/home-layout`(`routes/saved.js`)。

## 起動時に開くブラウザ
`ladytube.bat` で起動したときに開くブラウザを、管理画面の「起動時に開くブラウザ」(ネットワークの設定の下)で選びます。
ライブラリを切り替えたときの再起動では、今までどおり開きません。
- 選べるもの: 既定のブラウザ(最初はこれ)・Windows に登録されたブラウザ・場所を指定(.exe)・開かない。
  登録されたブラウザは、レジストリの `StartMenuInternet`(HKLM・HKCU・WOW6432Node)から読みます(Internet Explorer は除く)。
- ブラウザを選んだときは「起動のオプション」に引数を書けます(任意)。URL の前に渡し、空白を含む引数は `"…"` で囲みます。
  プライベートウィンドウは Chrome・Brave・Vivaldi が `--incognito`、Edge が `--inprivate`、Firefox 系が `-private-window` です。
  プライベートウィンドウでは、テーマや表示形式などの画面の設定がブラウザに残りません。
- 「今の入力内容で開いて試す」は、保存せずに今の入力内容で LadyTube を開きます。
- 安全のため:
  - 表示と変更はサーバーを動かしている PC からだけです(API は `pcOnly`)。
  - 受け付けるのは実際にある `.exe` の絶対パスだけで、引数は500文字まで・改行なし。起動はシェルを通さず、引数を配列で渡します。
  - 保存した `.exe` が後で無くなったときは、既定のブラウザで開きます(コンソールに出します)。
  - バックアップの書き出しに入れず、取り込んでも書き換えません(`.exe` の場所は PC ごとに違い、取り込んだファイルで `.exe` を指定させないため)。
- 保存先は DB の設定 `ext_browser`(`{ mode, path, args }`)です。全ライブラリで共通です(`library.js` の `SHARED_KEYS`)。
- 実装: `server/ext/browser.js`、API は `GET`/`PUT /ext/api/browser` と `POST /ext/api/browser/test`(`server/ext/index.js`)。
  本体の `server/index.js` の `openInBrowser` は `browser.js` の `openUrl` を呼ぶだけです。画面は `ExtSettingsSections.jsx` の `ExtBrowserSettings`。
